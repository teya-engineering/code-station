Bad deploy?
Send in the agent.

And the rest of
the window.

The parts you reach for between prompts, in the same place as the conversation.

Worktree sessions

Work in the project folder when changes should land there, or in an isolated checkout and branch when they should not. New sessions update main first.

Find in the chat

Press Cmd F to search a long conversation, with matches that follow the transcript as it grows.

Rewind and fork

Take a Claude Code conversation back to an earlier prompt and send it again, or fork it into a new session from that point.

Cost and context

Every session shows its spend next to the context meter. Any agent's settings can hide the figure.

Shortcuts

Save the commands worth having on hand, run and stop them from the composer, and keep saved prompts beside them.

Workspaces

Group projects into a workspace. The lead is the working directory and the rest join the same conversation, each in its own worktree.

MCP servers

Configure servers once and register them with any agent. Tag each with its environment, and sign in from a terminal when one asks.

Notifications

A notification when a session finishes a turn or stops to ask. Click it to open that session, or mark a session unread for later.

Updates in place

The app checks for new releases while it runs and installs them with one click, refusing any build that is not signed by the team.

Install it.
On your Mac.

Install with Homebrew, or download the signed and notarized DMG, drag Teya Code Station to Applications and open it. No toolchain, no build step.

Download for Mac View source on GitHub

What you need

  • macOS 15 or later
  • At least one agent installed and signed in: claude, codex or copilot
  • The app warns you when an agent's CLI is older than it needs
Homebrew
$ brew install teya-engineering/tap/teya-code-station
Build from source
$ git clone https://github.com/teya-engineering/code-station.git
$ cd code-station
$ ./build-app.sh
$ open "build/Teya Code Station.app"

Building needs Xcode 16 or another Swift 6 toolchain, and Git.

Make it yours

The parts that belong to your organisation rather than to the app, like the identity provider your APIs sign in against, your environments, your Grafana instances, skills marketplaces and the commands worth having on hand, live in one optional settings file the app reads at startup. Every section is optional, and so is the file.

The first-launch setup can read it from a local file or clone it from a Git repository, and build-app.sh can fold it into the bundle so the app you hand to your team is already set up. See the site configuration guide and the blank-slate example.
